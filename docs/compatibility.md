# Compatibility Matrix

This matrix is the Phase 7 compatibility contract for Claude Agent Team behavior in Codex Team. It classifies observable behavior, not only tool names.

| Behavior | Status | What Codex Team Provides | Boundary | Evidence |
|---|---|---|---|---|
| Durable team creation with leader identity | Supported | `TeamCreate` creates durable team state, scoped active binding, initialized storage, and `team-lead@<team_name>` identity. | State is stored in Codex Team SQLite runtime state, not Claude's team file implementation. | [Workflow test](../test/compatibilityWorkflow.test.ts) |
| Active-team inference across restart-style state reopening | Supported | Later tool calls can infer the active team after reopening a fresh MCP server against the same state root. | Inference is scoped to durable caller/workspace identity and fails clearly when context is missing or ambiguous. | [Workflow test](../test/compatibilityWorkflow.test.ts) |
| Named TeamMate identity through `Agent` | Supported | Named `Agent` calls in team context create stable TeamMate IDs such as `builder@alpha-team` plus member/run rows. | Backend execution remains separate from addressable TeamMate identity. | [Workflow test](../test/compatibilityWorkflow.test.ts) |
| Ordinary `Agent` without `name` remains ordinary subagent path | Supported | `Agent` calls without a TeamMate name return `ordinary_subagent_path` and do not create TeamMate rows. | Codex ordinary subagent behavior is not handled by the Agent Team layer. | [Workflow test](../test/compatibilityWorkflow.test.ts) |
| Explicit message persistence before backend delivery | Supported | `SendMessage` persists queued inbox rows and message events before attempting backend delivery. | Delivery may report backend limitations after persistence. | [Workflow test](../test/compatibilityWorkflow.test.ts) |
| Task create/update/list/get over SQLite task state | Supported | `TaskCreate`, `TaskUpdate`, `TaskList`, and `TaskGet` operate on team-scoped SQLite tasks and task history. | Task tools use Codex Team's durable task schema, not Claude internal task storage. | [Workflow test](../test/compatibilityWorkflow.test.ts) |
| Restart persistence for active bindings, messages, and tasks | Supported | Active bindings, queued messages, and task state survive restart-style MCP server reopening. | Persistence depends on the configured state root remaining available. | [Workflow test](../test/compatibilityWorkflow.test.ts) |
| `TeamDiagnostics` status summaries | Supported | `TeamDiagnostics` reports tool mapping, state summaries, lifecycle/run summaries, message/task summaries, and workspace review summaries. | Default output stays summary-oriented and avoids raw prompt, message, and task bodies. | [Workflow test](../test/compatibilityWorkflow.test.ts) |
| Workspace review safety and `needs_review` | Supported | File-modifying work is gated by isolation or reviewable diff requirements, and diagnostics expose `needs_review` review state. | Codex Team preserves review-needed state; it does not auto-merge or discard changed workspaces. | [Startup docs](startup.md) |
| Running-recipient turn-boundary queueing | Approximated | Messages to running TeamMates are persisted and queued for the next turn boundary. | This approximates async teammate delivery but is not live mid-turn injection. | [Workflow fixture](../test/fixtures/synthetic-claude-team-workflow.md) |
| Default backend execution with no configured runner | Backend-dependent | The default backend reports unsupported execution honestly instead of fabricating run/thread/process IDs. | Actual start/resume requires a configured execution backend with the needed capabilities. | [Tool mapping](tool-mapping.md) |
| Backend start/resume with durable metadata | Backend-dependent | The lifecycle contract records backend metadata when a configured backend can start, resume, or reconcile TeamMate work. | Behavior depends on backend capabilities and durable backend IDs being available. | [Tool registry](../src/tools/registry.ts) |
| Broadcast delivery through `to: "*"` | Unsupported | Broadcast requests are reported as unsupported rather than silently expanded. | `to: "*"` returns the unsupported broadcast boundary for v1. | [Tool mapping](tool-mapping.md) |
| Cross-session bridge delivery | Unsupported | Cross-session bridge delivery is not implemented in the v1 compatibility layer. | Messages stay within the durable team/runtime path; remote or cross-session bridge delivery is deferred. | [Phase context](../../.planning/phases/06-compatibility-validation-and-docs/06-CONTEXT.md) |
| Pane-style terminal UI | Backend-dependent | Optional pane mode can show TeamMate activity through tmux/iTerm2-style panes and TeamDiagnostics attach/status metadata when enabled and available. | This is a pane-style approximation; transcript experience is terminal scrollback and behavior depends on local backend support. | [Phase 7 validation](validation.md) |
| Exact Claude tmux/iTerm2 pane parity | Unsupported | The layer does not claim native Claude pane parity, hidden Claude flags, in-process approval UI, or exact tmux/iTerm2 behavior. | Codex Team remains an external compatibility layer with backend-dependent panes; it is not exact Claude tmux/iTerm2 pane parity. | [Phase context](../../.planning/phases/07-pane-style-teammate-ui-and-terminal-backends/07-CONTEXT.md) |
| Approval-bridge parity | Unsupported | The docs keep approval behavior outside the supported compatibility contract. | There is no approval-bridge parity with Claude's in-process approval UI. | [Startup docs](startup.md) |
| True Claude in-process runtime behavior | Unsupported | Codex Team runs as an external MCP compatibility layer. | It does not provide true Claude in-process runtime behavior. | [Phase context](../../.planning/phases/06-compatibility-validation-and-docs/06-CONTEXT.md) |
| AsyncLocalStorage-equivalent context | Unsupported | Durable active binding replaces process-local Claude runtime context for supported team operations. | It does not provide AsyncLocalStorage-equivalent context. | [Phase context](../../.planning/phases/06-compatibility-validation-and-docs/06-CONTEXT.md) |
| Hidden Claude CLI args | Unsupported | Codex Team exposes explicit MCP tools and documented runtime state. | It does not depend on or emulate hidden Claude CLI args. | [Phase context](../../.planning/phases/06-compatibility-validation-and-docs/06-CONTEXT.md) |
| Guaranteed mid-turn message injection | Unsupported | Messages are persisted and queued through explicit lifecycle paths. | It does not provide guaranteed mid-turn message injection. | [Validation docs](validation.md) |

See [Validation](validation.md) for the synthetic workflow, automated commands, coverage, manual checks, and known limits behind this contract.
